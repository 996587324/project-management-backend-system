# 小时产量删除工序保存修复

## 问题与处理

用户提供的 `/api/hourly-production/definitions` HTTP 400 响应包含业务消息“请完整配置接入类型、设备及SN/求和字段”。这是绑定完整性校验失败，前端原先把 HTTP 400 的具体原因替换成“服务器内部错误”，导致无法判断是哪条线的哪个工序有问题。仅凭该日志不能确认删除操作清空了绑定。

另一个已确认的问题是：删除总产出口径所指向的工序时，页面仍保留已删除工序的编码。即使其余绑定完整，也会被后端的总产出口径校验阻止保存。

本次修改：

- 删除操作捕获原线体、原工序对象，在确认后删除该对象，避免按延迟后的行索引操作错误的工序；取消操作正常结束。
- 工序规则和绑定编辑区域按线体/工序建立独立实例，切换、删除时不复用其他工序的编辑状态。
- 删除总产出工序后清空失效引用并提示重选，不自动改变统计口径；每条线保留至少一个工序。
- 保存前检查所有剩余绑定的设备、SN/求和字段，以及总产出口径。错误显示“线体 / 工序 / 第几个绑定”，并切到对应线体和工序。
- 后端仍严格校验绑定，增加线体、工序和绑定序号，便于直接接口调用定位问题。
- HTTP 4xx 响应优先显示后端的非空字符串业务消息；网络失败、服务端故障仍用原有通用提示。

未自动删除不完整绑定，未放宽绑定校验，未改写历史统计；不需要迁移数据库。
