# 小时看板选择修复与验证

## 原因

`/api/hourly-production/boards` 的旧实现返回 `Code/Name/Published`，页面读取 `code/name/published`。选项的值变成 undefined，默认看板也无法加载。

上次只修改了后端源码，但当前后端进程于 16:55:37 启动，运行 DLL 于 16:55:35 编译；控制器源码于 17:23:34 修改，因此当前运行实例未包含该修正。

## 本次修正

前端 API 层统一转换新旧字段名，确保页面获得有效的看板编码、名称和发布状态。不依赖后端立即更新，也不调整账号权限。

- `project-management-system/src/api/hourly-production-contract.ts`
- `project-management-system/src/api/hourly-production.ts`

## 验证

在原小时产量页面组件和真实 HTTP 客户端上，使用内存接口模拟当前旧服务格式：

1. 修改前复现：下拉框无有效选项，Vue 提示 ElOption.value 为 undefined，页面显示暂无看板。
2. 修改后默认加载第一看板，下拉列表能显示两个名称。
3. 鼠标选择第二看板后，标题和选中名称切换为第二看板，服务器收到对应运行数据请求。
4. 切回第一看板成功；输入“第二”搜索并选中第二看板成功。
5. 旧格式、新格式、混合格式、空列表及发布状态的脚本检查通过，相关文件 ESLint 通过。
6. 检查实际 3006 开发服务返回的前端模块，已包含本次兼容处理。
