# 微信 ClawBot 扫码反馈与双向调试变更

日期：2026-10-08。本文为新增迭代说明，不覆盖之前的说明文档。

## 使用方式

1. 进入“微信推送 → 我的微信推送”，点击“扫码绑定”。
2. 微信扫码后，网页显示“已扫码，等待手机确认”。若微信要求配对验证码，网页显示验证码输入框。
3. 完成确认后，网页显示绑定成功结果和提示。
4. 在微信向 ClawBot 发送一条文字消息。网页的“微信接收记录”自动刷新，收到消息后“消息会话”显示已建立。
5. 在“消息收发测试”输入内容，点击“发送测试消息”。结果及失败原因会显示在网页，发送记录同时保存到数据库。

页面自动刷新间隔为 5 秒，可关闭或手动刷新。后端收消息为原有的 iLink 长轮询任务，消息到达后才进入接收记录；网页刷新不直接向微信发起收消息请求。

当前支持保存和展示文字消息；图片、视频、语音和文件显示类型占位内容，语音有转写文本时显示转写，文件有名称时显示名称。此次未实现媒体下载、解密、预览或自动 AI 回复。

## 修改对照

| 位置 | 原行为 | 调整后 |
| --- | --- | --- |
| 二维码会话保存 | `ExecuteCommandAsync()` 未返回自增 ID，`sessionId` 可能为 0，网页直接跳过轮询 | `ExecuteReturnBigIdentityAsync()` 返回真实会话 ID |
| 网页扫码查询 | 每 3 秒开启一次请求，前端默认超时 15 秒 | 完成当前长轮询后再安排下一次；扫码接口超时 50 秒；关闭页面取消请求并忽略迟到响应 |
| 扫码状态处理 | 大部分状态退化为等待扫码 | 明确处理扫码、验证码、节点重定向、确认、过期、验证受限和失败，显示中文提示 |
| 二维码轮询节点 | 始终请求初始节点 | 保存合法微信重定向节点，后续请求跟随该节点 |
| 消息接收 | 仅更新游标和上下文 | 记录当前绑定微信用户的消息，按消息标识去重，消息和游标在同一事务提交 |
| 会话匹配 | 最后一个消息的上下文可能来自其他发送者 | 仅从当前绑定用户的入站消息获取上下文 |
| 用户测试发送 | 只有管理员调试入口 | 增加当前登录用户的个人测试接口，接收方由后端确定 |
| 投递记录保存 | 插入后返回的投递 ID 可能为 0 | 取回真实自增 ID，并显示发送成功或失败 |
| `X-WECHAT-UIN` | 对 uint32 的二进制字节编码 | 对 uint32 的十进制字符串进行 UTF-8/Base64 编码 |
| 上游业务结果 | `ret` 和 `errcode` 混合取第一个值 | 两项分别检查，避免 HTTP 200 或 `ret: 0` 掩盖业务失败 |

## 文件变更

- 修改 `Model/WeChatClawBot/WeChatClawBotEntities.cs`：绑定会话增加可空 `PollBaseUrl`；增加接收消息实体。
- 修改 `Model/WeChatClawBot/WeChatClawBotDtos.cs`：增加会话就绪状态、最近接收时间、个人测试请求、验证码请求、接收消息输出。
- 修改 `Interface/WeChatClawBot/IWeChatClawBotService.cs`：增加个人发送、接收查询，扫码查询支持验证码。
- 修改 `Service/WeChatClawBot/WeChatClawBotService.cs`：修复扫码 ID、状态机、节点切换、协议头；增加接收保存和个人测试逻辑。
- 修改 `Service/WeChatClawBot/WeChatClawBotDatabaseInitializer.cs`：初始化并兼容接收消息表。
- 修改 `calmadmin/Controllers/WeChatClawBotController.cs`：增加个人接收、个人测试发送和验证码接口。
- 修改 `calmadmin/Config/HostBuilderExtend.cs`：HTTP 超时至少保留 40 秒，满足长轮询需要。
- 修改前端 `src/api/wechat-clawbot.ts` 和 `src/views/wechat-clawbot/index.vue`：完善扫码提示和轮询，增加个人测试及接收记录。

## 新增接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/wechat-clawbot/binding/{sessionId}/verify` | 提交 `{ "verifyCode": "手机显示的数字" }` 并更新扫码状态 |
| GET | `/api/wechat-clawbot/me/messages?current=1&size=20` | 查询当前登录用户收到的微信消息 |
| POST | `/api/wechat-clawbot/me/test-send` | 提交 `{ "content": "测试内容" }`，向自己的绑定会话发送消息 |

这些接口需要本系统登录。个人发送接口不接受目标用户 ID；接收查询限定当前登录用户。管理员原有 `/debug/send` 接口保留。Bot Token、上下文令牌和游标不对前端输出。

## 数据库设计

新增 `WeChatClawBotInboundMessage` 表：自增主键 `Id`，所属后台用户 `UserId`，去重键 `MessageKey`，微信消息标识 `WeChatMessageId`，发送者 `SenderId`，类型 `MessageType`，内容 `Content`，微信发送时间 `MessageTime` 和后台接收时间 `ReceivedTime`。

`UserId + MessageKey` 为唯一索引；`UserId + ReceivedTime` 为查询索引。可能缺失的微信时间、消息标识明确允许 NULL。原绑定表增加的 `PollBaseUrl` 也允许 NULL，兼容已有记录。首个 ClawBot 请求或后台任务会执行结构初始化，不删除旧数据。

## 验证与发布

已在隔离 SQL Server 数据库配合模拟 iLink 响应验证：真实会话 ID、扫码与验证码状态、节点切换、绑定保存、上下文就绪、文字和媒体记录、重复消息去重、用户隔离、个人测试发送成功与失败。已验证新表初始化、旧表可空约束迁移及重复初始化；测试库已清理，未改业务数据库。

网页组件通过编译、代码检查和模拟交互验证，覆盖绑定成功提示、验证码暂停/提交、测试发送反馈、无并发扫码请求、关闭后忽略迟到响应。项目完整类型检查仍有其他既有错误，本次 ClawBot 文件未报告类型错误。

需要更新前后端并重启后端，不能只刷新旧后端进程。测试未使用真实手机确认，因此真实账号端到端扫码、接收和发送仍需按“使用方式”完成验证。
