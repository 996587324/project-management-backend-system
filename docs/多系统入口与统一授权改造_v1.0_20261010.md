# 多系统入口与统一授权改造 v1.0

日期：2026-10-10。本文为新增迭代说明，不覆盖以前的需求或 MCP 文档。

## 1. 本次落地范围

本次完成统一入口、授权基础、独立 B 前端、共享中文映射和 MCP 授权链路。**不是把 A 全部业务页面直接复制成 B**。

- 一个后台、两份独立前端构建。A 保留已有管理系统；B 首期提供独立数据工作台、共享模型/字段映射。
- 登录后先进入控制台，显示当前账号获准进入的系统。显示名称可配置，权限编码固定为 A、B。
- 系统菜单与账号权限独立配置。B 不继承 A 的历史角色。
- 模型中文名称、字段中文名称、单位、格式、值映射共用一套；B 从同一接收数据源读取最后已知字段值。
- A、B 共用标准 MCP V2，分别按账号在当前系统中的工具和资源授权执行。
- 尚未适配资源授权的旧业务 API，拒绝 B 和部分资源账号调用，不能仅靠隐藏菜单隔离。
- PDA、采集 Worker、实时持久化、AI 建议、微信队列业务本身不重写；不引入 Redis。

## 2. 当前架构

```text
密码登录 / TCL 单点登录
            │
            ▼
    A 站点统一控制台 /portal
            │ 按账号系统授权显示入口
     ┌──────┴──────┐
     ▼             ▼
A 原管理系统    B 独立数据工作台
A 动态菜单      B 独立路由组件清单
     │             │
     └──────┬──────┘
            ▼
       同一个后端
       ├─ 统一会话 / 系统授权 / 菜单分配
       ├─ 共享数据源、历史字段、最后实际值
       ├─ 共享模型与字段中文映射
       ├─ A 原业务（保留原权限与业务校验）
       └─ MCP V2：工具授权 + 资源范围 + 写确认 + 审计
```

B 不导入 A 的用户 Store、工作标签或整套动态路由。两个前端的本地缓存使用 `calmadmin:A:*`、`calmadmin:B:*` 命名空间。切换系统会取消未完成请求并重新加载授权菜单。

## 3. 登录与退出

### 3.1 三种令牌用途

| 类型 | 用途 | 能否调用原业务 API |
| --- | --- | --- |
| portal | 控制台、查看入口、申请进入票据 | 否 |
| app | A 或 B 的已授权业务 | 需同时满足系统、权限及资源检查 |
| mcp | MCP / 等价外部工具 API，专属 audience | 不能冒充普通后台令牌 |

统一会话有效期为 **20 分钟**。切换系统或获取用户 MCP 令牌不会重新延长会话；退出后所有派生令牌失效。SQL 中 UTC 时间读取后明确恢复 UTC 标记，避免 SQL datetime 丢失时区导致误判过期。

PDA 不过期令牌保持原逻辑，仅允许 PDA 对应接口使用。

### 3.2 进入 B 的流程

1. B 在自己的浏览器会话生成随机 verifier、state 和 S256 challenge。
2. 浏览器跳转 A 控制台；需要登录时先完成统一登录。
3. 控制台申请 B 票据，后端校验账号拥有 B 入口授权。
4. 后端只向管理员登记的固定 B EntryUrl 跳转，不接受请求方自定义 redirect URL。
5. B 用本地 verifier、state 兑换票据；票据有效 60 秒，数据库仅保存哈希。
6. 条件更新原子消费票据，并发、重复、错误系统、错误 state 均不能重复兑换。

URL 不携带长期 JWT。B 接收后立即从地址栏移除票据。本地 verifier 最多保留 20 分钟，服务器票据仍只有 60 秒。

### 3.3 退出与清理

前端清理本系统凭据，后台撤销统一会话，并沿用 TCL 单点登出。其他站点已有浏览器缓存不跨域直接删除，但其令牌会被后台拒绝。

现有用户日志后台任务每分钟附带清理临时凭据：票据过期五分钟后、会话过期一天后，每轮最多删除各 500 条。与业务历史数据清理无关。

## 4. 数据库和迁移

以下表由 SQLSugar CodeFirst 初始化；不改数据库连接配置、不删除原业务数据。

| 表 | 内容 |
| --- | --- |
| SysApplication | A/B 固定编码、可修改名称、固定入口、首页、启用状态 |
| SysUserApplication | 账号在某系统的授权；UserId + AppCode 唯一索引 |
| SysApplicationMenu | 系统所属菜单；AppCode + MenuId 联合主键 |
| SysPlatformAdministrator | 明确的平台管理员名单，不以普通用户通配权限自动提升 |
| SysPortalSession | 统一授权会话、到期时间、撤销时间 |
| SysApplicationLoginTicket | 哈希票据、系统、PKCE、state、有效期、消费时间 |
| SysApplicationMigration | 一次性迁移版本，防止重启重新授予入口权限 |

集合字段使用 `nvarchar(max)` JSON，避免批量项目授权被截断。可空时间列显式配置 `IsNullable = true`。会话和票据按过期时间建立索引。

第一次升级时：已有用户仅迁入 A，兼容历史权限和资源访问；历史 R_ADMIN/R_SUPER 迁为平台管理员；原菜单迁入 A，新增 B 菜单只属于 B。以后新增账号，包括 SSO 新建账号，不自动获得 A/B 入口，需要管理员分配。

首期 A 承担统一控制台，不允许停用 A；平台管理员不能撤销自己用于管理授权的 A 入口；A 菜单必须保留“系统入口与授权”。

原 `ExternalToolAccessLog` 新增可空 UserId、AppCode，机器客户端旧日志保持为空。原 `ExternalToolClient.ExpireTime` 明确可空。

原 SysUserOperationLog 新增可空 AppCode，操作事件的系统由服务端令牌确定，历史记录保持为空；查询 DTO 支持按系统过滤。B 独立记录按钮标签和页面，不采集表单值、令牌或消息正文。统一登录仍是一条会话，A/B 心跳不会重复计算同一个会话的在线人数。

## 5. 授权规则

- 入口启用 ≠ 菜单授权 ≠ MCP 工具授权 ≠ 数据资源授权。
- 后端菜单树先限制系统，再匹配账号权限。前端空权限不再解释为全菜单。
- 账号可配置线体、项目、边缘设备和数据源范围。空集合默认无资源，不自动认为“全部”。
- “全部业务资源”是显式宽授权；普通账号不默认开启。首次迁移的 A 账号保留旧资源行为。
- 数据源通过 `租户 + 设备` 复合键授权，界面可输入 `租户|设备`；后台转换为内部复合键。不能只按设备名匹配不同租户。
- 共享数据源查询先在数据库限制授权范围，再限制返回数量，最多返回 500 个源。
- 修改共享中文映射只允许平台管理员或显式 `shared-dictionary.write` 权限。普通系统管理员菜单权限、共享只读权限不会自动变成全局字典写权限。
- B 当前只注册工作台和共享字典组件；未知组件不能通过数据库菜单直接导入 A 页面。
- Agent WebSocket 也检查系统和资源边界；每次业务消息重新校验会话，不永久沿用建连时的权限。

旧 A API 仍保留各业务内部的管理员、按钮、数据校验。本次新增外层系统/菜单准入，**没有宣称所有旧接口已完成细粒度资源改造**。A 的部分资源账号请使用已适配的新查询接口或 MCP；旧接口会明确返回拒绝。

## 6. 通用模型与字段中文映射

复用原有：

- EdgeDashboardModelDisplayMapping：模型标识 → 中文名称/设备类别。
- EdgeDashboardModelFieldDisplayMapping：模型标识 + SourcePath → 中文字段名、单位、格式、精度、值映射。
- 原模型历史字段目录和设备最后已知值存储。

兼容表中的 `production-dashboard` 现在只是共享字典的固定物理存储分区，不再根据 A/B 或调用看板编码选择不同字典。旧 API 传入 A、B 或其他看板编码，都读取共享映射。

通用配置位于“共享模型与字段映射”。支持 xlsx/csv 导入、xlsx 导出；models/fields 工作表表头使用导出中的 camelCase 字段。导入按模型标识/原始字段路径合并已有配置，保留未提交字段。导入按模型逐项提交，**不是整个文件的数据库原子事务**；失败提示未全部完成，需检查已完成项目后重试。

原始数据字段不重命名，中文只作用于展示。保存路径采用历史目录原始大小写。报警规则、状态优先级、线体布局、卡片阈值仍按原业务配置，不在本次静默提升为全局配置。

如果旧库存在其他 DashboardCode 下的专属中文映射，本次保留这些历史记录，不自动覆盖或混入通用字典。升级前应导出核对，以共享字典为统一口径；冲突必须人工确定。本次未自动删除或迁移这些历史冲突记录。

## 7. MCP 的变化和兼容性

标准入口仍为 `POST /mcp/v2`，Streamable HTTP，由现有官方 .NET MCP SDK 处理协议。

**本次从匿名开放改为授权访问。** `/mcp` 旧入口和 `/api/external/v1` 等价工具接口同时保护，不能绕过 V2。现有匿名外部任务必须更新授权信息。

- A 顶栏“MCP 接入”、B 工作台可获取当前系统的用户专用 MCP 令牌。
- 请求头使用 `Authorization: Bearer <token>`。普通后台 app 令牌不能代替 MCP 令牌。
- tools/list 和 tools/call 均校验当前数据库授权；旧令牌不会永久保留已撤销权限。
- 读取不强制填写资源编码。部分资源账号省略编码时只查询授权子集，`scopeCurrent` 默认 1、`scopeSize` 默认 20，最多 50 个资源/页。
- 显式传未授权编码，在业务查询前拒绝；空授权集合返回空数据。
- 写操作保留明确业务参数、`confirm: true`；开始写入前必须成功保存 Attempted 审计，完成后保存结果。
- 用户 MCP 审计记录 UserId、AppCode；参数只保存摘要，不保存密钥或整份业务原始数据。
- 服务展示名继续使用原 MCP 配置，修改 A/B 的系统名称不会改变 MCP 服务名。

用户令牌受当前 20 分钟会话约束，不适合长期无人值守任务。长期外部任务使用已有外部客户端凭据换取专用机器令牌（30 分钟），并按需续期；每次调用重新检查客户端启用、有效期及授权。

当前资源模型覆盖线体、项目、边缘设备。用户审计和 ClawBot 需要独立的用户/接收人授权，**部分资源用户或机器客户端暂不开放这两类工具**；显式全资源且拥有对应 scope 的用户可使用。若现有外部微信推送任务依赖机器客户端，应先补独立接收人授权再切换，不应以匿名方式绕开边界。

既有免登录“公开生产看板”保持原有专门只读入口，并非受限系统的权限替代入口；它本身公开的线体数据仍可匿名查看。若某些线体要求保密，需另行收紧公开发布范围。

## 8. 管理员配置步骤

1. 升级后重新登录，旧后台令牌不包含统一会话信息，不能继续使用。
2. 在控制台进入 A，打开“系统入口与授权”（首期自动创建菜单）。
3. A EntryUrl 填写当前 A 站点的 `/#/portal`；B EntryUrl 填写部署 B 站点的 `/#/auth/entry`。
4. A 首页按原工作台路径；B 默认 `/workbench`。名称任意修改，AppCode 不变。
5. 选择用户，切换授权系统，开启入口并选择该系统权限。B 工作台权限为 `SystemBWorkbench`。
6. 共享字典只读为 `shared-dictionary.read`；可修改另加 `shared-dictionary.write`，谨慎分配。
7. 选择 MCP scopes、资源范围；不需要调用 MCP 的账号保持 scopes 为空。
8. 数据源批量填写每行 `租户|设备`，线体/项目/边缘设备填写各自业务编码，不混用。
9. 进入 B 验证独立菜单、授权源、中文映射及字段值。撤权后下一次 API 调用应被拒绝。

本次没有在开发机器或生产库中为真实账号自动授予 B，也没有代填生产 B 站点地址。

## 9. 前端构建与 IIS 部署

同一前端仓库，两个入口，避免复制共用组件：

```powershell
# A：原构建，输出 dist
pnpm build

# B：独立入口，输出 dist-b
pnpm build:b

# 开发 B：3007，.env.system-b 默认代理后端 localhost:8087
pnpm dev:b
```

A 原开发端口与环境配置保持；B 可独立修改 `.env.system-b` 代理目标，测试后台用 8089 时将 B 开发代理改为 8089。生产前端 API 仍通过各自站点代理到同一后台，不新增 xxtdxm 前缀。

IIS 新建独立 B 站点/端口，部署 dist-b；沿用项目既有前端代理配置模式，`/api/*` 转发同一后端（实际生产端口按现有部署，例如 8087），静态页面回退 index.html。B 配置不会自动修改 IIS。

外部 MCP 直接使用后台地址 `/mcp/v2`；若使用前端站点地址，需另外代理 MCP 路径，不能以为 `/api` 规则会包含 `/mcp/v2`。

TCL OAuth 回调仍是原后台 `/api/auth/oauth2/callback`，不需要为每个 B 页面新增 IT 回调登记；统一回调落到 A 登录页，再进入控制台。两站点所在机器必须均可访问后台及配置的 A/B 入口。

生产建议 HTTPS。PKCE 防止票据被直接兑换，但不能让明文 HTTP 的长期凭据免于网络窃听。
