# 微信 ClawBot 模型回答失败反馈 v1.4

日期：2026-10-17

## 本次目标

模型已调用工具但无法生成最终回答时，微信使用者应收到明确的失败提示，避免无反馈或误以为操作未执行。只读查询失败提示建议缩小查询范围，涉及写操作则要求先核对执行记录，不自动重跑业务工具。

## 使用者看到的内容

模型明确返回 `finish_reason: length` 或 `max_tokens` 时，提示达到输出长度限制，不将截断文本作为完整答案发送。

只读工具全部成功的示例：

> 本次回答达到模型输出长度限制，未能生成完整结果。
> 数据查询已完成，本次未修改业务数据。
> 建议缩小查询范围：指定一条线体、某台设备或更短的时间段，或一次只查询一个指标后重新提问。

对于空回答，仅提示可能与查询范围有关，不认定一定是输出额度不足。返回格式异常或模型不可用也使用安全的失败提示，不向微信发送异常堆栈、模型原始响应、凭据或内部请求信息。

已尝试执行写操作的示例：

> 本次回答达到模型输出长度限制，未能生成完整结果。
> 已有操作可能执行，请先到后台核对工具执行记录，不要重复提交；系统不会自动重试操作。

## 状态及安全边界

- 只读工具不再一律判定为可能产生写入。未知工具仍保守处理为可能写入。
- 错误提示进入现有微信发送队列，继续遵守授权、用户绑定、发送预算、发送间隔和投递审计。
- 任务先保存为 `ReplyPending`，下一轮只发送提示，不调用 Agent 或业务工具。
- 只读失败提示送达后，任务类型为“异常提示”，状态为“已回复”；这里表示提示送达，不表示模型已成功回答。具体失败原因仍可在模型调用日志中查询。
- 写操作失败提示类型为“操作核对提示”，发送后仍保持“结果待核对”，投递记录单独标明发送结果。提示发送失败也不会将业务结果误标为失败。
- 失败提示不附带可执行的确认标记，不允许通过回复“确认”误执行前一轮旧计划。
- 未调用工具的已知模型失败释放对话额度；已尝试业务工具的任务保留本次额度。
- 网页 Agent 同样使用安全失败提示。

## 验证与部署

- 离线模拟 HTTP 200 下的截断、空内容、null 内容、非 JSON 和正常回答，验证失败分类及模型审计。
- 使用真实 Agent Framework 配合模拟模型、模拟工具，验证失败后不重复调用工具。
- 随机隔离 SQL 数据库验证队列持久化、服务实例恢复后仅发送一次失败提示、只读与写入状态分离；不请求真实大模型，不发送真实微信消息。
- 前端微信 AI 及标签页组件回归测试。

部署需要更新后端并重启；前端更新用于显示新增提示类型的中文名称。本次未调大模型输出额度、未改变查询范围、未升级真实业务数据库、未重新执行历史失败任务。
