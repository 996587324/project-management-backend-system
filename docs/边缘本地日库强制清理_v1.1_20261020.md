# 边缘本地日库强制清理 v1.1

日期：2026-10-20。本文件为新增迭代说明，不覆盖历史需求。

## 规则

本地仍按 UTC 自然日创建 `edge-gateway-yyyyMMdd.db`，文件内表名不变。保留规则由“7个自然日，且上传完成后才允许删除”，调整为“超过4个工作日直接删除”，无论文件内消息为 Pending、Failed 还是 Uploaded，也不再读取完成标记判断是否可删除。

**会永久删除过期文件中尚未上传的数据，不能再通过本地队列补传。** 同时删除对应 WAL、SHM 文件，并记录一条强制清理警告日志。

工作日只按周一至周五计算，周六、周日不计；不包含法定节假日、调休等日历配置。本次按“超过”解释边界：计算文件日期之后到当前日期之间经过的工作日数，刚满4个保留，超过4个才删除。周末沿用最近周五的清理边界，不会额外增加一天的工作日年龄。

| 当前 UTC 日期 | 保留边界 | 删除范围 |
| --- | --- | --- |
| 2026-10-19，周一 | 2026-10-13 | 10月12日及以前 |
| 2026-10-20，周二 | 2026-10-14 | 10月13日及以前 |
| 2026-10-23，周五 | 2026-10-19 | 10月18日及以前 |
| 2026-10-24／25，周末 | 2026-10-19 | 与周五相同 |
| 2026-10-26，周一 | 2026-10-20 | 10月19日及以前 |

保持原清理触发机制：初始化时检查一次，之后每天首次读取上传队列时检查。UTC 换日对应北京时间08:00；并非独立的定时清理任务。服务停止或网关停用、不再读取上传队列时，不保证在跨日瞬间清理，待后续初始化或读取时执行。

本次不扩大自动补传范围，仍仅读取今天和未完成的昨天；保留窗口不等于自动补传窗口。

## 实现改动

- 新增 `Service/EdgeGateway/Database/EdgeLocalRetentionPolicy.cs`：四个工作日边界计算。
- 修改 `Service/EdgeGateway/Database/EdgeLocalDatabaseService.cs`：移除清理时的上传完成条件，改名清理方法；删除前关闭日库连接，记录清理警告。保留原 SQLite 连接字符串，兼容项目当前驱动。
- 新增 `tests/EdgeLocalRetentionSmoke/`：隔离临时目录、真实SQLite文件及工作日算法测试。
- 未调整中心SQL Server日志、WebSocket记录或数据追溯的保留规则，也不自动删除旧单文件 `edge-gateway.db`、其他前缀文件及无法识别日期的文件。

## 验证

隔离测试覆盖周中、周一、周六周日、跨周及刚满4个工作日的边界；Pending、Failed、Uploaded文件均删除；真实打开的SQLite连接关闭后可删除；对应WAL、SHM清理；损坏的过期文件无须打开即可删除；其他文件、旧单文件和边界文件保留；取消后可重试、同一天重复清理幂等。

```powershell
dotnet run --project tests/EdgeLocalRetentionSmoke/EdgeLocalRetentionSmoke.csproj
```

测试只操作随机临时目录，不运行生产采集或真实数据清理。部署并重启后新规则才会对实际文件生效；本次源码修改不主动清理现有运行数据。
