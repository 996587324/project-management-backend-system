# 推送中心与统一邮件推送 v1.0

日期：2026-10-20。新增迭代文档，不覆盖此前 MCP、微信及多系统文档。

## 一、实现范围

前端导航统一为“推送中心”，保留微信个人绑定、AI 连接、收发测试及记录；把原 Agent 中心的微信管理入口移入同一目录，新增邮件推送。微信原业务、账户绑定和权限检查不变。

邮件推送使用管理员统一配置的一套 SMTP 发件账户。普通用户只选择系统接收用户，不配置 SMTP、不接触授权码。配置修改权限按管理员角色判断，不按账号名称判断：当前有效账号需具有 `R_ADMIN` 或 `R_SUPER`，并具备当前系统的 `EmailPush` 功能权限。仅有 `*` 权限但不是管理员角色的账号不能读写配置。

本期不新增定时业务计划、不引入 Redis、不接入设备告警／工艺卡片的邮件规则，也不增加匿名 MCP 邮件发送。现有微信推送队列不改为邮件队列，两个渠道互不阻塞。

## 二、页面和动态菜单

```text

├─ 我的微信推送：保留原有五个 Tab

│  ├─ 发送邮件

│  └─ 发件账户配置：管理员角色可见，后端再次强制校验
└─ 微信管理与调试：保留原管理权限和 /agent/clawbot-management 地址
```

菜单整理不只修改前端模块路由：后端 `PushCenterMenus` 在系统菜单、多系统初始化之后执行一次性迁移，版本为 `push-center-email-v1`。

- 保留已有微信菜单主键、权限标识和启停状态；管理页面移到新父级时将旧的完整路径保存为绝对路径。
- 默认微信目录名称改为“推送中心”；自定义目录名称不强制覆盖。
- B 使用自己的菜单记录；已有 B 管理菜单的自定义名称、完整路径及启停状态保留，不修改 A 的菜单。
- B 未开放微信相关目录时，不自动开放整套推送中心；管理员可在系统入口与授权页面从组件目录添加。
- 新邮件功能仍需给普通用户显式授予 `EmailPush`，不自动提升用户或新增跨系统授权。管理员具有该系统通配授权时可以使用。
- 初始化器不再把微信管理重新补到 Agent 目录，防止重启后重复出现。

## 三、使用步骤

1. 部署更新后的后端和前端，刷新登录会话／菜单。后端启动后异步初始化邮件表，未就绪时邮件接口快速提示稍后重试。
2. 管理员进入“推送中心 → 邮件推送 → 发件账户配置”。
3. 配置 SMTP 主机、端口、登录账户、授权码、发件邮箱与名称。
4. 加密方式选择 `StartTls` 或 `SslOnConnect`；端口由实际邮件服务器决定，界面中的587、465仅是常见提示，不会自动切换。
5. 配置超时5～120秒、发送间隔1～86400秒、最大尝试次数1～5次。默认30秒、5秒、3次；“最大尝试次数”包含首次尝试。
6. 保存后可测试连接及认证，此操作不会发信。更改未保存时不允许测试旧配置，以免误判。
7. 启用后可显式确认“发送测试邮件到本人”，接收地址来自当前系统账号的邮箱资料，不是默认向发件邮箱发送。
8. 普通用户需具有邮件发送权限；选择收件用户、抄送用户，填写纯文本主题及正文，确认后入队，在发送记录中查看结果。

服务默认关闭；不自动导入 `appsettings.json` 中旧的 SMTP 密码。旧 `EmailOptions` 类型暂留兼容，但发送实现不再绑定或读取该配置节。

## 四、用户选择和发送边界

- 专用用户查询接口只返回选择邮件接收人所需的编码、账号、昵称、邮箱及有效状态，不调用需要用户管理权限的完整账户列表。
- 支持按姓名、账号、邮箱搜索、分页加载、选择已加载用户、批量选择搜索结果、清空。
- 单次收件人和抄送人合计最多100个不同用户；无有效邮箱的用户不可选，停用用户不提供选择。
- 前端提交用户编码，后端重新读取、校验邮箱，不接受普通用户指定发件账户。
- 同一邮箱去重，一位接收人一封投递，避免暴露其他人的邮箱。抄送投递使用独立的 Cc 信封，并不是在每位收件人的邮件中重复展开全部抄送列表。
- 任务保存接收用户和邮箱快照。真正发送前发现账号停用、邮箱变化或任务无效时取消该条投递，需要用户核对后重新提交，不静默改投新地址。
- 邮件配置通过版本号防止并发覆盖；更换登录账户时必须重新填写授权码。密码留空不覆盖现有凭据，不提供明文回读。

## 五、后台队列和结果

提交任务只执行校验和数据库事务，不连接 SMTP。后台消费者延迟启动，独立执行，失败不会导致 Web 主机退出，不阻塞登录或菜单接口。

使用数据库全局发送租约和间隔控制，多个进程不能同时绕过限速。任务和每位收件投递记录一起提交，避免半成品任务。任务请求具备发起人、系统、来源及幂等标识；相同请求不会重复入队，相同幂等标识对应不同内容时拒绝。

| 状态 | 含义 |
| --- | --- |
| Pending | 已入队，尚未发送 |
| Processing | 后台正在处理 |
| Retrying | 明确的暂时性失败，等待下一次有限重试 |
| Sent | SMTP服务器已接受；不代表收件人已收到或阅读 |
| Failed | 永久失败或达到最大尝试次数 |
| Unknown | 发送阶段超时／断线，或进程中断导致结果不明确；不自动重发 |
| Cancelled | 用户停用、邮箱变更或原任务无效，已取消 |

仅管理员可以手动重试 Failed／Unknown；Unknown 额外要求明确接受重复投递风险。每次重试另留审计，保存上一轮尝试次数；重试后重新计数。

停用服务会暂停待发送任务，不清空队列。保存配置时若已有发送或连接测试持有租约，会提示稍后重试，避免同一封邮件发送中途更换账户。

## 六、数据库和凭据

新增四张表，位于当前 `calmadmin` 业务数据库：

| 表 | 用途 |
| --- | --- |
| EmailPushSetting | 全局发件配置、版本、加密凭据、发送租约及下次发送时间 |
| EmailPushTask | 发起人、系统、来源、主题正文、请求幂等键及内容摘要 |
| EmailPushDelivery | 接收邮箱快照、实际发件邮箱和配置版本、状态、次数、失败原因及时间 |
| EmailPushConfigurationAudit | 配置修改、连接测试和人工重试审计，不保存明文凭据 |

除固定单例配置主键外，其余新增表均使用数据库自增主键；新增记录不手工填写自增编号。尚未发生的发送时间、租约时间保持 NULL，实体显式声明 SQL 可空；带数据旧表可重复迁移修复。中文主题、正文、发件名称和错误信息使用显式 Unicode 列。

SMTP授权码使用邮件专用 Data Protection 密钥环加密，目录为后端内容根目录下 `data/email-keys`。该目录必须持久化、备份并仅允许后端运行账号访问，不得作为前端静态资源发布。Windows额外使用当前运行身份的 DPAPI 保护密钥；更换IIS应用池身份或迁移服务器时，需要规划密钥迁移，或由管理员重新保存邮箱授权码。本期按单实例身份部署；不提供跨身份的自动密钥共享。

邮件密钥保护独立于现有微信和模型配置，不改变其密钥环。Autofac 扫描显式排除邮件初始化器和密钥保护器，避免覆盖已注册的单例、导致接口永远显示未初始化。

本期不自动清理邮件审计及历史任务，避免未约定保留周期时删除业务记录。

## 七、接口和 Agent

新增接口全部需要后台登录，继续校验当前 A/B 系统会话：

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/email-push/capabilities | 当前用户邮件管理能力 |
| GET /api/email-push/setting | 管理员读取脱敏配置 |
| POST /api/email-push/setting | 管理员保存配置，需匹配版本 |
| POST /api/email-push/test-connection | 管理员测试已保存SMTP连接及认证 |
| POST /api/email-push/test-send | 管理员向本人邮箱提交测试任务 |
| GET /api/email-push/recipients | 搜索、分页查询接收用户 |
| POST /api/email-push/send | 确认后提交任务，返回任务编号 |
| GET /api/email-push/records | 分页筛选记录；普通用户仅本人在当前系统发起的记录，管理员可看全部 |
| POST /api/email-push/records/{id}/retry | 管理员确认重试，可要求重复风险确认 |

项目管理 Agent 新增 `email.recipients` 查询实际用户编码；`email.send` 改为传入 `recipientUserIds`、`ccUserIds`、主题、正文，仍经现有执行计划确认后入队。已有 Agent 草稿和“发送当前回复”入口保留，改用统一选人组件及队列。邮件入口要求 `EmailPush`，原 Agent 邮件业务兼容 `AgentExecutor`；只有只读 `AgentAssistant` 权限不能发送邮件。

旧邮件地址参数仅作兼容：必须匹配启用的系统用户，不提供任意外部邮箱中继。Agent 执行使用执行上下文关联号生成幂等键；人机对话显示“已加入队列＋任务编号”，不再误报已经发送成功。微信 Agent 如调用邮件工具，继续使用显式渠道授权上下文，不伪造网页 JWT。

本次不向 `/mcp/v2`、`/mcp` 或 `/api/external/v1` 增加邮件工具，原匿名 MCP 模式不变。
