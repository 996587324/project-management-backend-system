# 独立工作任务与个人 MCP：首版实现与验证

依据：《独立工作任务与个人MCP_改造设计评审稿_20261026》《独立工作任务与个人MCP_产品与架构复审意见_20261027》

## 1. 首版功能

| 使用人 | 已实现内容 |
| --- | --- |
| 下发人 | 保存并恢复不完整草稿、明确要求和验收标准、选择工作组和主责人、指定验收人和日终接收领导、正式下发、修订、转派、取消 |
| 员工 | 查看本人任务、回复能否承担、承诺时间及里程碑、提出延期或协调事项、汇报进度及阻塞、讨论、上传文件和图片、编辑成果草稿、预览并正式提交 |
| 验收人 | 查看正式交付材料、通过或退回；退回后再次提交保留历史版本 |
| 管理者 | 查看授权范围的团队任务、处理延期、移交管理责任、查看不同视角的日终摘要 |
| 业务管理员 | 配置工作组、成员、业务角色和范围、日终时间/工作日/例外日期/渠道、查看运行概况及失败投递，并按权限重试 |
| 个人 MCP 使用者 | 创建限期且可撤销的个人凭证、读取本人任务、评估时间、汇报进展、上传真实文件、保存成果草稿；单独授权后才能正式提交或下载附件 |

前端入口为“工作任务”下的“我的工作”“团队工作”“工作设置”“个人 MCP 连接”。个人中心也提供个人 MCP 入口，均按实际权限显示。

本业务使用独立工作组和独立任务数据，不要求关联项目，也不复用原项目任务、项目文件表。

## 2. 已落实的关键规则

1. 默认需要验收。进度达到 100% 不代表完成，正式提交后进入待验收；只有选择无需验收的任务才在提交时直接完成。
2. 要求修订、人员转派、排期与成果版本均保留记录。首次承诺时间保留，申请延期不会直接覆盖已生效的承诺。
3. 员工未提交的成果草稿及未共享附件不向领导泄露；正式提交与进展中明确关联的材料才按权限共享。
4. 同组主管可按范围查看任务，但修改要求、转派等还必须是该条任务的当前管理责任人；指定验收人单独获得验收能力。
5. 未完成任务不能随成员移除而失去责任人。管理员可以移交失联或停用领导的管理责任，该操作只显示必要标识，不开放任务正文。
6. 角色与范围按一条授权组合判断，不把不同角色的范围拼接成额外权限。平台管理员默认获得配置权，不能因此阅读任务正文。
7. A、B 应用数据、授权和个人凭证分别隔离。A 初始化工作菜单，B 只登记可用组件，需要 B 管理员明确添加菜单并另行授权。
8. 写操作使用请求编号及版本校验。重复同次请求返回原回执，相同编号替换内容或旧版本结构性修改会被拒绝。

## 3. 默认参数与首次启用

### 3.1 角色配置

沿用现有登录账号和应用准入，在模块中新增四类业务角色：

| 角色 | 用途 | 范围 |
| --- | --- | --- |
| worker | 员工执行任务、个人 MCP | 本人；仍受本人主责任务关系约束 |
| dispatcher | 编辑和下发任务 | 指定人员、工作组、工作组树或全域 |
| supervisor | 团队监督、管理及验收 | 指定人员、工作组、工作组树或全域；变更、验收另查任务关系 |
| work-admin | 管理业务组织与授权 | 指定人员、工作组、工作组树或全域；不能越权授权 |

先由现有平台管理员进入“工作设置”，创建工作组、添加已有账号，再给员工授予 worker、本组管理者授予 dispatcher 或 supervisor。只有有执行资格且在相应组内的人员才能成为可下发的主责人。修改授权后需要刷新用户权限或重新登录，使菜单显示与后台当前权限同步。

### 3.2 附件存储

建议使用宿主机环境变量配置：

```text
WorkTasks__StorageRoot=D:\CalmAdminData\work-task-files
WorkTasks__MaxFileBytes=20971520
WorkTasks__MaxUserBytes=524288000
WorkTasks__UnlinkedFileHours=24
```

这些是配置示例，没有写入现有敏感配置文件。未指定时，目录为 Windows 公共应用数据目录下的 `CalmAdmin/work-task-files`。部署服务账号须有读写权限，文件目录必须位于发布替换目录之外。

多实例部署需共享同一个可靠持久目录；数据库与附件一起备份并验证恢复。当前实现为文件系统存储，尚未接入对象存储，也未执行备份恢复演练。

默认单文件 20 MiB、每人 500 MiB。支持 JPG/JPEG/PNG/WEBP、PDF、UTF-8 TXT/CSV、DOCX/XLSX/PPTX；校验扩展名、实际文件内容和 Office 包结构，拒绝伪装图片、目录穿越和不合法 Office 包。这里的校验不能替代杀毒引擎，未接入恶意文件扫描服务。

上传先申请短期票据，再传输实际字节并完成校验，校验通过后才可关联进展或成果。上传票据约 15 分钟有效；个人凭证撤销后，相关未用票据也会失效。过期临时上传和超过保留期未关联的文件会清理，正式关联材料不会被该清理任务删除。

### 3.3 日终同步

初始不启用自动日终投递。管理员确认后在“工作设置”启用，并明确工作日、例外上班/休息日期、时区、时刻、员工接收口径及渠道。默认参数为上海时区、工作日 17:00、站内收件箱、延迟补发窗口 120 分钟；这些参数不代表已向现有员工启用。

后台约每 30 秒检查一次；按应用、业务日期、接收人、视角生成持久摘要。员工只看本人任务，领导看授权团队范围。重复执行不会重复建同一份摘要，之后修改任务不会改写既有摘要；阅读和实际发送前还会重新检查当前权限。

可选邮件、微信复用现有发送队列和账号绑定。微信仍尊重已有推送开关、账号状态和有效会话。外部渠道仅同步状态数量及系统入口，任务要求、标题和材料详情留在受控站内页面。通用渠道记录不能用于绕过业务授权重发工作任务通知；无法确认是否已发送的状态不自动重发。

此次没有向真实邮箱或微信发送测试消息。实际发信配置、微信账号绑定、渠道到达率和真实接收效果仍需部署后联调。

## 4. 个人 MCP 连接

入口：`https://部署域名/mcp/work-tasks`，使用支持自定义请求头的 HTTP MCP 客户端，在每次请求中携带：

```text
Authorization: Bearer <在个人页面新建时显示的个人凭证>
```

凭证只显示一次明文，服务端保存摘要；默认有效期 30 天，可设置 1 至 90 天，支持立即撤销。轮换方式为先新建、更新客户端，再撤销旧凭证。个人页面可查看工具调用名称和结果等元数据，不展示原密钥、文件正文或任务请求内容。

能力为 `read / assess / report / upload / submit / download`。服务端省略范围时默认只读；页面默认勾选读取、评估、汇报和上传，正式提交与材料下载须另行勾选。凭证不授予下发、转派、团队阅读或验收能力，拥有主管角色也不能通过此个人入口读取团队数据。

工具包括本人列表/详情、评估回复、进展汇报、成果草稿/正式提交、附件申请/完成/小文件上传/下载及写入回执查询。小文件工具解码上限 256 KiB，普通文件走申请上传票据、HTTP PUT 实际字节、完成校验三步。

已通过真实 MCP SDK HTTP 协议初始化与工具调用验证。尚未实现 OAuth 授权发现和浏览器授权登录，也未指定并逐一测试某款第三方桌面客户端；不支持自定义请求头的客户端不能直接使用这一版个人凭证。反向代理应同时转发 `/mcp/work-tasks` 与相关 `/api/work-task-uploads` 路径，使用 HTTPS，并允许配置范围内的上传大小。

## 5. 架构与数据变更

新增 Model/WorkTasks、Interface/WorkTasks、Service/WorkTasks、工作任务控制器、个人凭证中间件与后台任务。网页和 MCP 共用同一个领域服务，避免两套状态流与权限校验。

共 19 张独立表：`work_group`、`work_group_member`、`work_role_grant`、`work_task`、`work_task_revision`、`work_task_plan`、`work_task_milestone`、`work_task_report`、`work_task_submission`、`work_task_review`、`work_task_attachment`、`work_task_attachment_link`、`work_task_audit`、`work_personal_key`、`work_command_receipt`、`work_task_outbox`、`work_task_digest`、`work_notification_delivery`、`work_notification_rule`。

后台启动时运行可重复初始化，使用数据库事务和应用锁协调多实例。专项检查在真实 SQL Server 中验证了新建、重复初始化、保留旧行补充可空列、实际 NULL 与非中文排序规则下的中文内容保存。时间以 UTC 保存，对外返回带时区时间，未发生的节点使用 NULL。

现有系统只增加模块装配、菜单权限投影、消息队列业务来源及独立 MCP 路由。原匿名 MCP 工具目录没有加入个人任务工具。没有修改原项目任务的数据模型。

发布建议先备份并在预发布环境启动后端，确认新表和索引初始化成功，再发布对应 A/B 前端；多实例按现有发布流程逐个替换。前后端构建通过不代表已完成线上无感部署、容量和故障恢复验证。

## 9. 复现与发布核对

在后端仓库运行核心专项检查：

```powershell
dotnet run --project tests/WorkTaskSmoke/WorkTaskSmoke.csproj
```

默认仅创建随机测试数据库，连接本机 `(localdb)\MSSQLLocalDB`，不读取生产连接配置。也可用 `WORK_TASK_SMOKE_SQL` 指定专用测试 SQL Server，但仍只在其上创建随机测试库。执行账号需有创建、删除测试库权限。

浏览器复现可设置 `WORK_TASK_UI_HOLD=1` 后运行同一测试程序，程序将输出临时回环地址并暂时保留隔离后端。在前端仓库将该地址设置为 `WORK_TASK_UI_API`，执行 `pnpm exec tsx scripts/preview-work-tasks.ts`，打开其输出的专用测试页面。测试入口只用于本机隔离验证，不能配置到正式反向代理中。

后端构建为 `dotnet build calmadmin/calmadmin.csproj`；前端 A/B 分别为 `pnpm exec vite build` 与 `pnpm exec vite build --mode system-b`。注意默认构建会写 dist/dist-b；本次验证显式改为工作区独立产物目录，以保留原工作区状态。

如需回退应用版本，保留新增业务表和附件目录，恢复匹配的旧程序及前端；不要为回退而直接删除新增数据。正式环境的旧库初始化、回退与备份恢复仍需预发布演练。
