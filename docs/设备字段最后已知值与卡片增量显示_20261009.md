# 设备字段最后已知值与卡片增量显示

版本日期：2026-10-09。本文件为新增迭代说明，不覆盖以前的变更文档。

## 修复的问题

设备接收的是增量报文。以前最新快照被整条覆盖，卡片直接读取该报文，未出现在下一帧的字段就显示为空。本次保留原始报文，同时建立设备字段当前值表：新报文只更新明确上报的字段，展示时重建设备完整状态。

示例：

```json
{"data":{"temperature":25,"status":2}}
{"data":{"count":10}}
```

第二条到达后，卡片仍读取 `temperature=25、status=2`，同时得到 `count=10`。

## 新表与保存规则

中心业务数据库新增 `EdgeGatewayRealtimeDeviceFieldLatest`，由启动初始化创建。

| 字段 | 用途 |
| --- | --- |
| Id | 自增主键 |
| TenantMark、DeviceCode | 隔离租户和设备 |
| SourcePath | JSON Pointer，例如 `/data/temperature` |
| SourcePathHash | 大小写敏感路径的 SHA-256；与租户、设备组成唯一索引 |
| ModelMark | 设备模型 |
| ValueJson、ValueType | 原值与类型；明确空值保存 JSON `null`，不是 SQL NULL |
| SourceTimestamp、DataTime | 该字段最后明确上报的源时间 |
| MessageId、ReceiveTime | 上报消息标识与该字段接收时间 |
| CreateTime、UpdateTime | 当前值行建立、更新的时间 |

该表是当前状态，不是每条报文历史表。同一个字段更新同一行；不做日表、7 天清理，也不引入 Redis。对象另存结构标记，数组整组保存。

- 字段未上报：保留旧值，且不改变该字段最后明确上报的时间。
- 明确 `null`：清空；`0`、`false`、空字符串均是有效值。
- 嵌套对象：递归合并；空对象不代表清空旧对象。
- 数组：整组替换，不拼接；减少元素时旧元素不会保留。
- 父节点改为 `null`、数组或标量：删除此前的子字段，避免旧值重新出现。
- 新设备没有上报过的字段：没有实际值，不使用同模型其他设备的样例填充。
- 明确更换模型：清除原模型当前值；省略模型、数据类型时保留既有元信息。
- 延续原来的时间顺序策略：比该设备最新快照更早的整条报文被忽略；双方都有 Unix 毫秒时间戳时直接比较时间戳，避免 SQL datetime 舍入影响判断。
- 重复同一消息、时间、值不会增加字段行。同时间不同内容仍按后到达的明确字段更新。

`SourceTimestamp、MessageId、ModelMark` 显式允许 SQL NULL；其他新表非空列都在插入时赋值。字段路径限制 512 个字符，数组/值用 `nvarchar(max)` 保存。

## 数据链路和兼容范围

1. `EdgeRealtimeDataService.ReceiveAsync` 接收 HTTP 实时数据。
2. 原始快照与字段最新值在同一个事务内保存，失败一起回滚。
3. 样本 `Data` 为合并后的设备状态，供状态、产量统计使用；`ReportedData` 为本次实际增量，供历史字段目录和追溯触发使用。
4. 卡片运行数据、数据源字段选择、生产看板机械手/设备组件展示及产量读取，通过批量字段查询重建完整状态。
5. 设备卡片 AI 建议和调用卡片运行接口的 Agent/MCP，复用修正后的卡片数据。

卡片追溯只检查本次明确上报或清空的字段。缺失字段不产生变更、误恢复事件，也不额外写入追溯检查点。明确空值可以产生变更记录；数值告警对非数值/空值不生成数值恢复事件。

在线/离线仍按设备报文接收时间判断。离线后保留最后值，但卡片状态显示离线，不能把保留数值理解成设备仍在线。

原始 `EdgeGatewayRealtimeDeviceSnapshot.DataListJson` 继续保存最近一条报文。原始快照查询接口仍返回原报文，不被重构数据覆盖。旧 `dataList` 格式延续现有展示第一组 `Data` 的逻辑，本次不合并多组业务块。

本次覆盖卡片已有的 HTTP 实时数据源链路；WebSocket 接收历史日志、参数追溯表并没有自动转换成 HTTP 卡片数据源，没有新建第二条采集链路。

前端卡片响应结构兼容，页面继续读取 `displayValue`，无需增加浏览器端缓存，本次未修改前端文件。

## 启动和历史补齐

- 启动时只创建新表和索引，不在查询请求中执行 CodeFirst。
- Web 启动后延迟 30 秒，以每批 100 台设备补齐旧快照，批间让出时间；失败记录日志并重试。
- 补齐与实时接收共用进程内写锁，写入前重新读取设备快照；已有最新值的设备不再回灌旧报文。
- 新增实时报文不等待后台补齐：第一条增量会先补上该设备自己的旧快照，再合并新报文。
- 补齐期间，尚未生成字段行的设备临时读取自己的原始快照。
- 以前已被覆盖、丢弃的字段值无法从现有快照可靠恢复，需要源头重新上报完整值。不会拿其他设备或模型样例当实际值。
- 当前写锁适配既有单后端进程部署；多实例同时接收同一设备时，需要再增加数据库级设备写锁/并发重试，不能把进程内锁当跨实例锁。

## 另外发现并修复的 SQL 约束

真实告警保存测试发现 `EdgeDashboardDeviceCardAlertRecord.ClaimExpireTime、PushedTime` 没有显式允许 SQL NULL，导致尚未认领/推送的告警插入失败。

已给实体增加 `IsNullable=true`，并在 CodeFirst 前执行可重复的旧表修复。已有记录、主键和推送筛选索引保留；不填写虚假的认领或推送时间。
