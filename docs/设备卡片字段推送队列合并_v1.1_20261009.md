# 设备卡片字段推送队列合并 v1.1

日期：2026-10-09。本文是新增迭代说明，不覆盖《设备卡片字段微信推送_20261009.md》。

## 1. 调整结果

原来：字段变化写入数据库待发任务，后台逐条向微信发送。

现在：仍然使用 SQL Server 持久化消息队列，按可配置间隔收集消息；同一后台用户、同一微信绑定的多条变更合成一条微信消息。没有额外部署 Redis、RabbitMQ，也没有新增周期业务查询计划。

接收数据时只写业务数据和待发任务，不等待微信网络请求。队列和间隔都存入数据库，服务重启不会丢弃未处理任务。

## 2. 配置入口和具体行为

入口：设备卡片配置 → 字段推送记录 → 全局队列发送间隔 → 保存间隔。

- 默认 5 秒，支持整数 1～86400 秒，适用于全部线体的**设备卡片字段系统推送**。
- 最早待发任务等待满配置时间后，后台取同一接收人、同一微信绑定的可发送任务合并。新加入队列且已提交的任务也可被本轮收集。
- 每轮只发送一个接收人的一个合并包。发送尝试结束后，至少等待配置间隔才尝试下一包；不同接收人也错开发送，而不是每 5 秒同时发出一批独立请求。
- 保留每一条已产生的事件及原始内容，包括窗口内的报警和恢复。**不是只保留最后一个值**，不会把“报警后恢复”压成一条正常状态。
- 每包最多收集 50 条、正文最多 10000 字符；超出的任务继续等待下一轮，没有静默丢弃。此限制与现有微信发送服务的长度校验保持一致。
- 单条消息保留原模板；多条消息增加“设备字段变更汇总 / 共 N 条”标题，用分隔符连接各条内容。
- 合并不会混合不同用户和不同微信绑定；重新绑定微信后的旧任务继续按原规则取消。

例如：用户 A 在窗口内收到温度变化、设备状态变化和报警恢复，共三条任务；发送给 A 的实际微信消息只有一条，但队列仍有三条可追溯记录。用户 B 的消息会在后续间隔发送，不与 A 同时突发。

### 两个间隔不要混淆

“字段变化冷却时间”控制字段普通变更多久允许生成通知，阈值/首次基线/上下限规则保持不变。

“全局队列发送间隔”控制已生成通知怎样合并和限速。它不会自动把字段原来的 300 秒冷却改为 5 秒。如果需要每个有效变化都进入队列，可把对应字段变化冷却设为 0，再由全局队列合并发送。

后台按约 1 秒频率扫描；实际到达时间还受启动延迟、微信请求耗时、接收人数、队列积压影响，5 秒不是保证送达的硬实时承诺。保留原有启动后延迟 30 秒启动发送工作器，避免重启立即发送积压消息。

## 3. 持久化、并发和失败处理

新增 `EdgeDeviceCardPushQueueSetting` 表，固定单例主键 `Id = 1`（非自增配置键）：

| 字段 | 用途 | 可空 |
| --- | --- | --- |
| IntervalSeconds | 全局间隔，SQL 默认值 5 | 否 |
| NextSendTime | 下一次允许尝试发送的时间 | 是 |
| LeaseOwner | 当前后台处理器租约标识 | 是 |
| LeaseExpireTime | 当前租约过期时间 | 是 |
| UpdateTime | 配置修改时间 | 否 |

数据库条件更新认领全局租约，使使用同一数据库的多个服务实例不能同时发包。原任务也通过条件更新认领，发送前续租。租约为 10 分钟；处理中断的任务过期后标为结果未知，不自动重新发送，以避免对已经收件的消息重复推送。

每条原始任务继续记录尝试次数、状态、失败原因和发送记录 ID。同一合并包内的任务共享 `DeliveryId`；“字段推送记录”新增发送记录 ID 列，可在微信发送记录中定位完整合并内容。

- 成功：包内每条任务标记已发送。
- 明确失败：每条任务仍按原来的最多 3 次、30/120 秒退避规则处理，并同时受全局间隔限制。
- 会话未就绪：标记暂不可发送，需修复会话后人工重试。
- 结果未知：整包对应任务标记未知，不自动或直接人工重发，先核实微信收件情况。
- 停用或配置移除：沿用原来的取消逻辑。
- 改间隔不会清空已有租约或已经保存的下一次发送时间，不会触发瞬间补发。

本迭代不改变外部 MCP 推送、微信调试直接发送的既有行为；队列适用于当前设备卡片字段自动推送。没有新增历史任务清理策略，原始任务仍保留作审计。

这只能降低高频发送风险，不能保证完全避开微信侧风控。消息产生速度持续高于发送速度时，会出现积压；应结合字段阈值、冷却时间和接收人数控制业务量。

## 4. 接口

后台登录鉴权保持与现有设备卡片推送配置一致，不开放到免登录看板。

- `GET /api/EdgeGateway/dashboard/device-card-push/queue-setting`：查询全局间隔。
- `POST /api/EdgeGateway/dashboard/device-card-push/queue-setting`：保存 `{ "intervalSeconds": 5 }`。
- 原 `recipients / tasks / test / tasks/{id}/retry` 接口继续使用；测试消息也进入合并队列，不绕过间隔。

非法间隔返回业务 400。接口不返回内部租约信息。

## 5. SQL 兼容

实体新表使用 SqlSugar CodeFirst。所有尚未发生的发送/租约时间显式允许 SQL NULL，非空字段新增时有有效初值，固定配置键不使用自增插入。

已有非空配置表缺少 `IntervalSeconds` 时，先补 `int NOT NULL DEFAULT (5) WITH VALUES`，保留现有主键、行和其他列；迁移可重复运行，已有间隔不会重置。

当前 SqlSugar 版本在 `DbMaintenance.AddColumn` 携带默认值时会触发无效 `Object` 表查询；该兼容补列使用受控表名的显式 DDL。常规建表、任务读写、租约、分页、状态更新仍使用 SqlSugar。
