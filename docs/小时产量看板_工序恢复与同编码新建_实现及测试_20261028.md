# 小时产量看板：工序恢复与同编码新建

日期：2026-10-28。状态：代码实现完成，隔离环境验证完成，未正式部署或推送 Git。

## 使用方式

进入“小时产量配置 → 线体、工序与数据”：

1. **新增工序**：删除并保存后可以重新使用原编码。新工序独立统计，不再因为该编码存在历史记录而拒绝保存。
2. **已移除工序 / 恢复 → 恢复原工序**：回填原设备、字段和统计规则，继续关联原历史。恢复时统计规则为只读；如需换设备或改变统计方式，使用“同编码新建”。
3. **已移除工序 / 恢复 → 同编码新建**：保留相同显示编码，重新配置数据绑定，使用新的统计身份。原工序历史和报表继续保留。
4. 选择恢复或新建后，都要点击“保存全部配置”才生效。尚未保存的移除也能撤回恢复。

同一条线的当前配置仍不能同时存在两个相同编码；需要先移除当前工序，再恢复其他历史实例。线体总产出口径仍须指向当前启用工序，移除总产出工序后需要重新选择。

## 统计与历史规则

- 显示编码与统计身份分离。旧工序沿用原来的线体/工序键，新实例分配独立内部键，用户不需要手工编写该标识。
- SN 去重、返工判定、小时桶和运行看板都使用统计身份。相同编码、相同 SN 的新实例不会被旧实例的去重记录抑制，也不会合并旧产量。
- 恢复原实例保留原统计口径，原 SN 去重规则继续生效。调整名称、对齐行、目标等展示配置不会因此重写已生成的报表。
- 后续新增或恢复设置生效边界；保存前接收的报文、事件时间早于恢复时刻的报文，不因恢复而自动补算。新看板保留原有离线过站能力。
- 已经冻结的报表不改写，报表任务键不变，恢复不会自动重发历史小时报表。
- 移除实例的小时桶不参与新实例的数量和数据更新时间计算。
- 保存配置、移除和恢复身份在同一数据库事务内提交，保留版本检查及数据库锁。配置变化时，旧快照的待处理报文留待下一轮处理，避免旧、新配置同时写入。

## 旧数据兼容

新增表 `HourlyProductionProcess`，保存工序身份、完整配置、启用状态及实际发生的移除/激活时间。配置 JSON 增加 `instanceId`、`creationMode`、`activeSince`；身份和生效时间由服务端决定，不能通过修改请求冒用旧身份。

启动初始化会登记当前工序，也会识别过站表、小时桶中已经移除的旧编码。保留原过站记录、小时桶、主键及报表，不批量改写原始统计。首次补齐内部元数据不增加业务配置版本。

以前已经删除且未保存完整配置的工序，不能假定能还原原设备和字段。系统明确标记原配置缺失，禁止伪造恢复，但允许使用相同编码新建，原历史保留。未知的移除时间和原配置保持 NULL，不填当前时间或最小日期掩盖缺失。

发布时应统一升级运行小时统计的后端实例，再使用新功能，避免新旧统计程序混跑。使用新实例身份后，不应直接回退到不识别身份的旧后端继续处理数据；回退需要先停止相关统计处理，并采用匹配版本或经验证的数据恢复方案。正式发布前应完成数据库备份及旧库初始化时间验证。本次未执行正式环境升级、负载测试或备份恢复演练。

## 修改位置

- 后端：小时工序模型、初始化、配置保存、归档读取、过站处理和运行数据查询；新增身份迁移与生命周期服务。
- 新接口：`GET /api/hourly-production/definitions/{code}/removed-processes?lineCode=...`，需要当前应用的配置权限，并检查看板及数据源范围。
- 前端：配置页、工序编辑、绑定编辑、看板复制。复制看板时清除旧统计身份，避免副本继承原历史。
- 测试：扩展现有 `HourlyProductionSmoke`，新增 `HourlyReaddSmoke` 和本机专用浏览器验证入口。
