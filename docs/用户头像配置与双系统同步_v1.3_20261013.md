# 用户头像配置与双系统同步 v1.3

日期：2026-10-13。本次新增说明，不覆盖前面的迭代文档。

## 功能与使用

点击右上角头像菜单 → 个人中心 → 更换头像 → 选择图片 → 拖动、缩放、裁剪 → 生成预览 → 保存头像。

- 默认继续使用前端现有 `src/assets/images/user/avatar.webp`。
- JPG、PNG、WebP，上传文件不超过 2MB；原图边长 16～4096 像素，总像素不超过 800 万。
- 服务端验证实际图片内容，拒绝损坏图片、动画、多帧及非图片，统一重编码为 512×512 PNG，不保留原始文件名或图片元数据。
- 个人中心可恢复默认；顶部菜单、个人中心、锁屏同步显示。
- 头像属于后台账号，不属于系统 A 或系统 B。同账号在两边共用；重新打开或聚焦另一系统时同步最新头像，无循环轮询。
- 固定个人入口为 `/#/account/profile`，使用完整后台布局，必须登录当前系统，但不需要用户管理菜单或业务数据全量权限。
- 原有动态个人中心组件仍可复用；原有账号管理、密码业务没有改为头像接口。

## 接口

所有接口仅从有效的当前系统 JWT 解析账号，不接受用于指定归属的 `userId`。平台入口令牌、匿名请求、已注销会话、MCP 专用令牌不可用于个人头像操作。

| 请求 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/user-profile/avatar/info` | 当前账号头像版本和地址；禁止缓存 |
| GET | `/api/user-profile/avatar?v=版本` | 当前账号 PNG 内容；未设置或文件丢失返回 204，前端使用默认头像 |
| POST | `/api/user-profile/avatar` | multipart/form-data，字段 `file`，上传当前账号头像 |
| POST | `/api/user-profile/avatar/reset` | 当前账号恢复默认 |

上传、重置、信息接口统一返回 `data.avatar` 和 `data.avatarVersion`，恢复默认时二者为 null。`/api/UserInfo/GetUserInfo` 也返回这两个字段。

前端通过统一 API 地址配置拼接接口，以 Authorization 请求头读取图片，再生成临时 Blob 地址显示；不把 JWT 放进图片 URL，不将 Blob 地址存入用户持久化状态。退出、账号切换时撤销旧 Blob 并丢弃迟到响应。头像元数据请求超时 15 秒，不阻塞用户信息和菜单初始化。

## 数据库与文件部署

在 `sys_user_info` 新增 `avatar_file_key`，长度 64，显式 `IsNullable = true`。老账号保留默认头像，新增账号无需伪造头像值。现有系统数据库初始化会执行兼容的 CodeFirst 升级，不删除或重建用户表。

图片文件独立存储，数据库只保存随机文件标识，不保存图片字节或浏览器 URL。默认目录为后端内容根目录下 `data/user-avatars`。

生产建议配置持久化目录并备份目录及用户数据库，避免部署覆盖后丢失图片。可在部署配置中加入（本次没有改动真实 appsettings 文件）：

```json
{
  "UserAvatar": {
    "StorageRoot": "D:\\ApplicationData\\calmadmin\\user-avatars"
  }
}
```

也可设置环境变量 `UserAvatar__StorageRoot`。相对路径以内容根目录解析；IIS 应用池/服务运行账号需要该目录的读写权限。A/B 前端不需要另加公开图片代理，沿用现有 `/api` 代理即可。

每次成功替换或恢复默认会清理该账号的旧随机头像文件；保存失败清理未提交的新文件，不删除现有头像。清理失败记录警告，不回滚已经保存的头像。文件目录不对匿名用户公开，不允许客户端提交文件路径。

升级需要发布并重启后端，然后重新构建发布 A/B 前端。测试构建输出放在工作区 `.codex-temp/avatar-a`、`.codex-temp/avatar-b`，没有覆盖已有 dist，也没有重启真实服务、操作生产数据库或推送 Git。
