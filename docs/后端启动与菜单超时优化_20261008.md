# 后端启动与菜单超时优化（2026-10-08）

## 问题与证据

此前正在运行的后端中，`GET /api/Menu/GetMenuTree` 直连耗时约 14.65 秒，经过前端代理的一次请求超过 16 秒，触发前端 15 秒超时。请求线程停在 `CodeFirst.InitTables → AddRemark/DeleteColumnRemark → SqlCommand`，即在读取菜单前维护表结构和字段注释。数据库采样还观察到实时快照、字段目录写入的 SQL 编译资源等待。

模型调用在服务开始监听后执行，不是菜单请求的直接等待点。本次没有通过延长前端超时掩盖问题。

## 修改对比

| 业务 | 修改前 | 修改后 |
| --- | --- | --- |
| 动态菜单 | 每次读取依次建表、补菜单和修改默认权限 | 请求只读取菜单并组装树；缺失菜单在启动时补齐 |
| 用户、角色、普通账号登录 | 请求中反复检查用户/角色表、补默认角色 | 初始化集中到启动阶段；请求不再维护结构和默认数据 |
| 用户列表 | 分页前额外同步读取全表 | 去掉无效的全表读取，保留分页查询 |
| 既有配置 | 读取菜单时可能覆盖排序、图标、角色、隐藏标记 | 默认初始化不改已有菜单和角色权限；管理页面保存仍正常生效 |
| 后台数据库上下文 | AI、微信并行账号等可能继承同一上下文 | 每轮任务独立上下文；每个并行账号独立上下文；事务内复用同一实例 |
| 模型字段目录 | 每条报文通过常规列表更新生成带变化值的大段 SQL | SqlSugar `Fastest.BulkUpdateAsync`，只更新需要变动的列，每批最多 200 条 |
| SQL 日志 | 同步向控制台输出原始 SQL | 默认仅慢 SQL/异常；记录指纹、耗时、操作名称和 TraceId，不输出 SQL 内容及参数 |
| 请求日志 | 缺少统一慢请求诊断 | 记录慢请求、失败及取消请求的路径、状态、耗时和 TraceId，不记录查询参数、请求体、Token |
| 启动诊断 | 多个表和索引初始化只有总耗时 | 按系统菜单模块、EdgeGateway 表组、索引维护步骤记录耗时 |

## 日志配置

未改现有 `appsettings*.json`。可按需要新增以下配置，或使用对应环境变量：

```json
{
  "BackendDiagnostics": {
    "SlowRequestMilliseconds": 1000,
    "SlowSqlMilliseconds": 500,
    "LogAllSql": false
  }
}
```

`LogAllSql=true` 也只输出执行信息和 SQL 指纹，不输出原始语句及参数。SQL 和 HTTP 日志使用 Activity TraceId 关联；后台 SQL 记录业务操作名称。

## 保持不变的行为与边界

- 前端代理、15 秒超时、API 前缀、OAuth/JWT、数据库连接配置和 SqlSugar 包版本不变。
- 历史字段继续保留，新字段即时插入，已知字段的最新值、累计次数及最后接收时间仍逐条保存；首见时间和创建时间不被批量更新覆盖。
- 默认菜单缺失时仍补齐，只是从每次请求移到每次启动；既有菜单/角色配置不覆盖。
- 必要结构初始化仍先于 HTTP 监听，不会让业务接口访问尚未建好的表。本次并非把全部启动初始化扔到后台，首次建库及真实结构升级仍可能有启动耗时。
- 已运行进程未被停止或重启，必须重新编译并重启后端或重新发布才会加载修改。
- 工作区原本存在未提交修改；本文件只描述本次优化，不能把当前全部 `git diff` 都视为本次新增。

## 验证结果

1. 完整后端编译通过。保留已有 AutoMapper 安全告警、可空性及其他原有警告，未在本次擅自升级依赖。
2. 随机隔离数据库验证空库创建、真实插入和带已有数据的重复初始化；自定义菜单权限、图标、排序、隐藏状态和角色权限均保留，无重复菜单。
3. 真正 JWT 授权的 `GetUserInfo` 控制器返回成功；12 个并发 `GetMenuTree` 请求均成功；采集到的 SQL 无结构维护、默认数据写入。
4. 多轮隔离测试中，12 个并发菜单请求约 0.38～0.71 秒。这是测试数据库/测试宿主的结果，并非生产环境验收承诺。
5. 8 个并行数据库事务中，4 个提交、4 个故意回滚，互不影响；同一事务跨 await 保持上下文一致。
6. 真实字段目录插入与 BulkUpdate 验证通过，覆盖 Unicode、引号、NULL、新字段、历史字段、首见时间、最新值和累计次数。
7. 实际 Autofac 注册及 CopyNew 后慢 SQL 计时验证通过；参数中的测试敏感字符串未出现在日志中。
8. 微信扫码反馈、验证码、会话就绪、接收去重、用户隔离、测试发送、失败审计及长轮询期间解绑回归通过（模拟 HTTP + 隔离数据库，不操作真实微信账号）。
9. 测试用随机数据库均已删除，没有修改业务数据库。
